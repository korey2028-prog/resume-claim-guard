# resume-claim-guard

一个小型 Agent Skill，用来检查 AI 改写后的简历有没有把经历写得超过事实。

大多数 AI 简历工具做的是把简历往 JD 上靠。这个 Skill 做相反方向的事：把每一条表述拉回你能拿出证据的事实。它回答一个问题：**这句话，面试官追问或背调核实时，你站得住吗？**

## 它会检查什么

- **动词越级**：“参与”写成“主导”、“原型”写成“上线”、AI 辅助写成“独立开发”。角色和交付阶段分两条轴检查，互不替代。
- **无来源的数字和结果**：用户量、转化率、提分、播放量，以及换了单位或对象的数字，比如把“120 条报名记录”写成“服务 120 名用户”。
- **事实底稿自己的矛盾**：底稿也会写错，比如“使用工具期间成绩提升”，但第一次考试比工具早。它会先自检，不会照着错的底稿放行。
- **多个版本之间的不一致**：投给不同公司的定向版里，同一段经历写法不同。已经投出去的版本，会给出面试时的统一口径。
- **过期数字**：粉丝数、用户数这类会变的数字，按记录日期区分“过期”和“作废”。

## 一分钟开始

**第一步：你用的是什么？**

| 你用的工具 | 怎么接入 |
|---|---|
| 豆包、ChatGPT、Kimi、DeepSeek 等网页聊天 | 打开 [PROMPT.md](PROMPT.md)，复制整段粘贴进对话框，然后上传简历。不用安装任何东西 |
| Claude Code | 对它说：`把 https://github.com/korey2028-prog/resume-claim-guard 克隆到 ~/.claude/skills/resume-claim-guard` |
| Codex | 对它说：`把 https://github.com/korey2028-prog/resume-claim-guard 克隆到 ~/.codex/skills/resume-claim-guard` |
| 其他支持 SKILL.md 的 Agent | 把仓库放进它的 skills 目录 |

**第二步：你手里有什么？**

| 你有 | 它会怎么做 |
|---|---|
| 只有一份简历（最常见） | 逐条追问你“这句里你本人做了什么、上线了吗、数字从哪来”，把回答整理成事实清单，你确认后再审计 |
| 原版简历 + AI 改过的版本 | 对比两版，揪出 AI 加进去的动词、数字和结果，只追问这些 |
| 投给不同公司的几个版本 | 另外列出各版本之间写法不一致的地方，已投出去的版本给面试统一口径 |
| 已经整理好的经历清单 | 直接审计 |

简历可以是 PDF、Word、HTML、Markdown 或直接粘贴的文字。

**第三步：说一句话**

```text
用 resume-claim-guard 审计我的简历。不要替我编任何经历。
```

在 Agent 里用这一句就够了；用网页版时，提示词里已经包含了这句话的意思。

## 输出

1. 输入与限制
2. 事实底稿自检
3. 每份简历的状态计数
4. 逐条表格：原文、拆分后的主张、对应事实、证据状态、角色上限、阶段上限、问题、建议
5. 跨版本不一致和面试统一口径
6. 修改建议稿
7. 需要你确认的清单
8. 未决项

证据状态分五种：`confirmed`、`supported`、`needs-source`、`inference`、`rejected`。定义见 [SKILL.md](SKILL.md)。

## 人工边界

它只做审计，给出改写建议。事实、动词上限和最终文本都由你确认。它不会投递简历、发送消息、登录招聘账号，也不会把审计结论写回你的事实底稿。

如果你在 HTML 源文件里用 `<!-- F-01 -->` 这样的注释绑定事实编号：导出 PDF 时注释会被去掉，但 HTML 源文件本身仍然保留注释，不能直接对外发送。注释只是指针，写了编号不代表这条表述成立。

## 示例

两组都是虚构候选人：

- [single-html](examples/single-html/)：一份 HTML 简历，展示动词越级、编号无法解析和编号泄露；
- [multi-version](examples/multi-version/)：两份从 PDF 提取的定向版，展示底稿自身矛盾、已作废口径、过期数字和跨版本不一致。

## 范围

v0.1 只做简历和求职文本的主张审计。岗位跟踪、浏览器填写、面试训练和自动生成 PDF 都不在范围内。
